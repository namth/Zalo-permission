## 1. Executive Summary

A comprehensive performance, latency, and database architecture audit was conducted across the OmniAgent Platform to resolve slow page response times, high AI Agent dispatch latencies, and cross-region database network bottlenecks.

Prior to optimization, every message sent by a user to Thảo Chi Bot suffered from a **6–8 second pre-inference latency** due to 7–8 sequential cross-region database roundtrips (each ~1,100ms roundtrip from Vietnam to Supabase Tokyo and Neo4j Aura Cloud) before the LLM could even be triggered. In the Admin Dashboard, the Skills page suffered from a severe **N+1 Cypher query bottleneck** taking 20–25 seconds to load, and server startup was plagued by 50+ sequential DDL migration roundtrips taking upwards of 50 seconds.

## 2. Root Cause Analysis & Architectural Remediation

### 2.1 Cross-Region Distance & Latency Bottleneck
- **Physical Reality**: The server runs on a Raspberry Pi local network in Vietnam (`192.168.1.36`). PostgreSQL is in Tokyo (`aws-0-ap-northeast-1.pooler.supabase.com:5432`) with roundtrip ping = **1,109ms**. Neo4j Aura Cloud ping = **1,164ms**.
- **Impact**: Any flow that executes queries sequentially multiplies the 1.1s network penalty by $N$.
- **Remediation**:
  1. Converted sequential queries into concurrent `Promise.all` wherever independent.
  2. Implemented low-latency local Redis caching (local Redis roundtrip < 1ms) for high-frequency resolution data.

---

### 2.2 Agent Dispatcher Latency (Pre-LLM Roundtrips)
- **Bottlenecks Identified in `apps/agent-worker/src/dispatcher.ts`**:
  1. `runCypher` for resolving Workspace from `ChannelChat` or `ZaloGroup` (~1,150ms).
  2. `ContactService.upsertFromMessage` sequentially executed (~1,100ms).
  3. Neo4j Cypher query for Skills (~1,150ms).
  4. Prisma query for Skills (~1,100ms).
  5. Neo4j Cypher query for Tools and ToolGroups (~1,150ms).
  6. Prisma queries for ToolGroups and WorkspaceToolConfig (~1,100ms).
  7. Neo4j Cypher query for Vault Master & Scoped Variables (~1,150ms).
- **Remediation Implemented**:
  - **Chat Workspace Mapping Cache**: Stored in Redis under `cache:chat_ws:${platform}:${chatId}` with 30-minute TTL.
  - **Workspace Context Cache**: Implemented `getWorkspaceContext(workspaceId, redis)` caching all resolved skills, candidate tools, tool groups, and base scoped variables under `cache:ws_context:${workspaceId}` with a 3-minute TTL.
  - **Parallel Contact Identification**: `ContactService.upsertFromMessage` now runs in parallel with workspace context retrieval via `Promise.all`.
  - **Safe Identity Injection**: Caller identity parameters (`CALLER_SENDER_ID`, `CALLER_ROLE`, `CALLER_PLATFORM`) are safely injected into a cloned scoped variable map per message without cache pollution.

---

### 2.3 Neo4j Driver Connection Leak & N+1 Queries
- **Driver Leak in `packages/database/src/neo4j.ts`**:
  - `getNeo4jDriver()` checked `if (process.env.NODE_ENV !== 'production') global.neo4jDriverGlobal = driver;`. In production, this condition evaluated to false, causing every single Cypher invocation to instantiate a brand-new unmanaged `neo4j.driver` instance with a 50-connection pool.
  - **Fix**: Driver is now cached in both module scope and global scope across all environments with `maxConnectionPoolSize: 25`, `connectionAcquisitionTimeout: 20000`, `maxConnectionLifetime: 3600000`, and `disableLosslessIntegers: true`.
- **N+1 Cypher Queries in `GET /api/admin/skills`**:
  - Iterated through every skill in a `for` loop calling `neo4jClient.getSkillRelations(skill.id)`. For 20 skills, this caused 20 roundtrips (20 × 1.16s = 23.2 seconds!).
  - **Fix**: Created `neo4jClient.getBatchSkillRelations(skillIds)` executing a single Cypher query with `WHERE s.id IN $skillIds`. Reduced Cypher execution from 23.2s to 1.1s.

---

### 2.4 Sequential Queries in Admin Tools & Workspaces
- **Tools API (`GET /api/admin/tools`)**:
  - Previously ran `db.query(query)`, `db.query(countQuery)`, `db.query('SELECT ... FROM tool_groups')`, and `neo4jClient.run(...)` in series (4.5s).
  - **Fix**: Wrapped all 4 queries in `Promise.all` (1.2s total).
- **Workspace Tabs in Admin (`workspaces/[id]/page.tsx`)**:
  - Replaced sequential fetches with `Promise.all([fetchTools(), fetchAllTools()])`, `Promise.all([fetchUsers(), fetchAllUsers()])`, and `Promise.all([fetchSkills(), fetchAllSkills()])`.

---

### 2.5 Startup DDL Migration Penalty in PostgreSQL
- **PostgreSQL Pool Initialization (`apps/web/src/lib/db/postgres.ts`)**:
  - `ensureWorkspacesSchema` ran ~50 DDL statements (`CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ADD COLUMN`, `DO $$`) sequentially in a `for` loop on startup/initDb. Over the Tokyo link, this held connection pool resources for 50+ seconds.
  - **Fix**: Guarded with `isSchemaEnsured` / `isSchemaEnsuring` and bypassed auto-execution on the request path in production unless `AUTO_MIGRATE_SCHEMA=true`.
